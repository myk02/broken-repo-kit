02

The checker's clean room

It trusts your code. It does not trust your tests.

What goes into the room

Only the part you were asked to change, plus the kit's own tests.

  • ✓Your library code: minishop/
  • ✓The kit's hidden fail-to-pass tests
  • ✓The kit's hidden pass-to-pass tests
  • ✓A fresh temporary folder, deleted afterwards
Why: a correct fix should not depend on editing the tests, the test config, or the task description.

What is left outside

These are checked for tampering, then ignored by the run.

  • ×Your copy of the tests
  • ×Your conftest.py or pytest.ini
  • ×Any file changed outside minishop/
  • ×Your environment variables and pytest options
Result: editing a test does not earn a pass. It is reported as a violation before pytest starts.
03

Two questions, two test groups

A score is only fair when both answers are yes.

Fail-to-pass

Did the bug get fixed?

These hidden tests fail on the broken code and must pass on the fix. They cover the edges the prompt never shows.

task 001 0 / 5 → 5 / 5
Pass-to-pass

Did anything else break?

The whole visible suite runs again against your code. It must stay green, including parts of the shop the task never mentions.

task 001 101 / 101 both before and after
Both greenmeans the fix is real and nothing else moved.
04

Why the score is trustworthy

The checker is tested like a product, not a script.

Hidden cases

The prompt is not the test

You see a few examples. The checker knows many more: boundaries, unicode, ordering, empty inputs.

Fresh copy

Your tests never run

Only minishop/ is copied. The verifier and visible tests come from the kit.

Deterministic

Same answer every time

No clock, no network, no random values left to chance. Three repeats must agree exactly.

Proven traps

Wrong fixes are tested too

26 plausible wrong fixes are run. Each one must be rejected for the right reason.
